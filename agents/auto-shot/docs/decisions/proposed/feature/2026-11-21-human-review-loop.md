# 决策：切点人工复核闭环

状态：proposed

## 问题

ffmpeg 的 scene score 对低对比度的切点不敏感：从特写切到更宽的场景时，色调可能一致、画面只有局部变化，分数低于阈值就漏切。把阈值从 0.3 降到 0.25 会提高召回（同一集 508 → 624 镜），但也会引入闪光、黑场、快速运动造成的伪切点。单靠一个阈值无法同时解决漏切和误切。

需要一个不污染事实层、可回退、人能快速上手的修正流程：发现问题 → 可视化核对 → 导出修正 → 生成新镜头表。

## 决定

1. **默认阈值降到 0.25**，`--threshold` 仍可继续降低以换取召回；阈值变更必须和复核一起使用，不把低阈值结果当成最终镜头表。
2. **`auto-shot review` 生成单文件 HTML**：播放器 + 镜头列表，点击/←→跳到切点前 0.6s 播放；勾选“误切”，按 `m` 记录漏切；标记存 `localStorage`，可导出 `review-flags.json`。页面不需要服务器，视频用相对路径引用。
3. **`auto-shot apply-review` 消费导出文件**：
   - `falseCuts` 把该镜并入前一镜；
   - `missedCuts` 在指定时间切分所在镜头；
   - 重编号 `S001..Snnn`，被人工改过的镜头 `source=manual`，新切点写入 `manual_cuts`；
   - 结果另存 `shots-reviewed.json`，原 `shots.json` 不变；应用后必须通过全部质量门。
4. **复核是例外处理，不是主流程**：页面用来抽查和修正，不替代更好的检测器。后续 M1 接可替换 SBD（PySceneDetect/TransNetV2/OmniShotCut）后，复核仍然是低置信度镜头的兜底。
5. **导出文件是普通 JSON**，不引入数据库或服务端状态；页面刷新后 `localStorage` 仍在，换浏览器/清缓存会丢标记，因此重要修正要及时导出。

## 备选方案

- **只调阈值，不做复核**：0.3 漏切，0.25 引入闪光伪切，0.2/0.15 更多；无法同时满足。否决。
- **做完整时间线编辑器**：能拆分/合并/拖动，但工程量大，且当前只需要切点核对；先把最小闭环做出来。
- **直接手改 `shots.json`**：容易破坏时间轴连续性和镜号，且没有 `manual` 标记；否决。
- **让 VLM 直接判断切点**：代价高、不可复现，且单帧/双帧不足以判断转场；先把 VLM 用在逐镜标签，切点核对留在人工闭环。

## 后果

- 低阈值结果的召回更高，但需要人看一遍；这是当前检测器能力下最诚实的做法。
- `shots.json` 保持不可变，修正结果单独成文件，便于对比和回退。
- 复核页是开发/审片工具，不是产品 UI；后续接入播放器或编辑器时可以复用同一份 review JSON 契约。
- 人工修正会进入 `manual_cuts`，自动重跑不能覆盖，满足镜头表契约。
